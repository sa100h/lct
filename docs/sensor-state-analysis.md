## 3. Переходы состояний (день t → t+1, последовательные дни)

Базовый паттерн: **доминирующие состояния чрезвычайно «липкие»** (98–99% самопереходов). Сигнал — в редких переходах.

**Пожарная охрана:**
- Норма → {Норма 0.93, Обнаружен дым 0.04, Неопределен 0.03}
- Обнаружен дым → {**Норма 0.72**, дым 0.19, Неопределен 0.06} ← сам гаснет за 1 день в 72% случаев
- Неисправен → {Норма 0.89}

**Диспетчерский контроль:**
- Обесточен → {**Обесточен 0.91**, Норма 0.06, Есть питание 0.03} ← липкое, долго
- Выключен → {Выключен 0.95}
- Норма → {Норма 0.68, Выключен 0.21, Обесточен 0.08}
- Есть питание → {Обесточен 0.95} ← «есть питание» часто сразу уходит в обесточен

**Охранная подсистема:**
- Норма → {Норма 0.98, Движения нет 0.01}
- Движения нет → {Движения нет 0.98, Норма 0.02}
- Не замкнут → {**Норма 0.99**} ← кратковременное, сразу восстанавливается

**Газовая / Температурная:** Норма → {Норма ≥0.99} (почти нет переходов).

**Диагностическая:** Норма ↔ Питание от батарей (Норма→батареи 0.08, батареи→Норма 0.10) — реальный цикл ИБП.

## 4. Пути смены состояний (по типам)

Однонаправленные короткие цепочки, без многоступенчатых пре-алармов:

- **Пожар:** `Норма → Обнаружен дым → (Норма | продолжение дыма)`. Линейный, без предвестников; «ранний сигнал» = сам момент onset. Длительность дыма: медиана 1 день, p95 2, **макс 5 дней**.
- **Охрана:** `Норма ↔ Движения нет` (оба липкие); `Не замкнут → Норма` (99%). Не замкнут: медиана 1, **макс 2 дня**.
- **Инфраструктура:** `Норма → Выключен` (фон) и `Норма → Обесточен` (событие). Обесточен: медиана 2, p95 4, макс 119. Выключен: медиана 3, p95 17, макс 302.
- **Газовая:** `Норма → Обнаружен газ` (17 случаев за 8 лет) → сам гаснет (макс 1 день).
- **ИБП:** `Норма ↔ Питание от батарей` — нормальный цикл, батарея держит p95 12 дней.

**Onsets в критические состояния** (вход в критичное, пред. день не был):

| Подсистема | Onsets | На 100k пар | Куда |
|---|---:|---:|---|
| Пожарная | 1967 | 3350 | 100% → Обнаружен дым |
| Диспетчерский | 11746 | 1425 | 99% → Обесточен (+ Неисправен 109, Отключено 38) |
| Охранная | 444 | 186 | 91% → Не замкнут (+ движение 42) |
| Газовая | 17 | 85 | Обнаружен газ |
| Темп / ИБП | 0 / 1 | — | — |

Критические состояния **транзиторны** (дым ≤5дн, не замкнут ≤2дн): метка «критичен или нет» перепомечает; честная ранняя метка — **onset** (вход в состояние).

## 5. Предложения по использованию

1. **Onset-метки для ML (прямая связь с планом sensor-failure).** Критичные состояния — это транзиторные входы, а не устойчивые условия. Метка фазы 1 «сбой / переход в критическое» = `critical(t) AND NOT critical(t−1)` — честный ранний сигнал; steady-state «критичен» даст искусственно завышенный AUC (это и есть находка о 83% positives в старом feature-файле).

2. **Сuppression по run, а не по дню.** При 98–99% самопереходах аларм «на каждое критичное канало-день» — шум. Генерировать событие на **старт нового run** (onset), игнорируя продолжение. Сокращает поток на порядок.

3. **Марковские базлайны + аномалия отклонения.** Построить цепь Маркова (P(состояние | пред. состояние)) на тип/подсистему. Редкий переход (напр. fire `Норма→дым` = 4%) — и есть аномалия. Отклонение эмпирической частоты переходов от базлайна = детектор «что-то изменилось в динамике датчика».

4. **Слой качества/живучести датчика как фича.**
   - 19.5% канало-дней **без отчётного состояния** (нет данных);
   - 4014 каналов из 11485 имеют <100 дней (мёртвые/отключённые);
   - «Пропал датчик» само по себе предиктивный признак сбоя. Фичи: доля дней с отчётом за N дней, длина текущего gap, число restart-циклов. Это самые дешёвые и сильные фичи для sensor-failure.

5. **Dwell-time фичи.** Ожидаемая длительность (тип × состояние): дым > p95(2дн) — необычно; Обесточен > p95(4дн) — другая операционная проблема. Расхождение фактической длительности с ожидаемой = ранний индикатор.

6. **Тип-кондиционированные модели, а не одна общая.** 6 подсистем → 4 категории, но внутри категории алфавиты состояний сильно различаются (дым ≠ обесточен ≠ не замкнут). Разумнее: модель на подсистему/тип, или type-кондиционированные фичи. Одна «мега-модель» размывает семантику.

7. **Ограничение разрешения.** Данные дневные: «onset» = разрешение день, внутридня порядок потерян. Для систем с событием < 1 дня (дым, газ) раннее предупреждение ограничено этим разрешением — либо нужна более мелкая агрегация, либо честно позиционировать как «выявление за день».

### Приоритет (рекомендуемый порядок)
1. Onset-метки (п.1) → переобучение sensor-failure — уже в плане.
2. Фичи живучести/gap (п.4) — дёшево, высокоинформативно.
3. Run-suppression алармов (п.2) — сразу снижает шум в проде.
4. Марковские аномалии (п.3) — отдельное направление, требует валидации.

---

### Данные качества (красные флаги)
- **19.5%** канало-дней без состояния — пропуски/неотчётность.
- **4014/11485** каналов <100 дней за период — мёртвые или поздно подключённые.
- Частота канало-дней стабильна по годам (365/366/365/…/180 дн в 2026) — агрегат полон, пропуски на уровне каналов, а не датасета.
