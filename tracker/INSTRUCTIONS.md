# Как работать с трекером (GitScrum-стиль)

Планирование хакатона живёт **в этом репозитории**, а не в Jira/Trello.
Вся «система» — это git: задача = markdown-файл, статус = поле в файле,
PR = единица работы, дашборд = автогенерируемый раздел README.

```
tracker/
├── README.md            ← этот файл + краткое описание
├── INSTRUCTIONS.md      ← подробная инструкция (вот она)
├── config.toml          ← спринт (название, даты, ёмкость) и дедлайны хакатона
├── gen_dashboard.py     ← пересобирает канбан-сводку и burndown в README
├── build_seed.py        ← (пере)создаёт seed-задачи LCT-01..12
└── tasks/
    ├── LCT-01.md        ← 1 файл = 1 задача
    └── ...
```

## 1. Где что находится

| Что | Где |
|---|---|
| **Backlog (бэклог)** | задачи с `column: Backlog` — это файлы `tracker/tasks/*.md`. Их список виден в колонке **Backlog** дашборда в README |
| Вся доска (канбан) | раздел `📋 NicePlan` в `README.md` (между маркерами `<!-- NICEPLAN:BOARD -->`) |
| **Новые задачи добавляются** | в `tracker/tasks/` — новый файл `LCT-<номер>.md`, см. раздел 3 |
| Спринт и ёмкость | `[sprint]` в `tracker/config.toml` |
| Burndown | раздел `⏳ Burndown` в README, автособирается из задач |

Канбан-колонки (порядок движения задачи):

```
Backlog → To Do → In Progress → Review → Done
 🗃️        📋         🔨            🔎        ✅
```

## 2. Значение колонок

| Колонка | Когда туда | Связь с git |
|---|---|---|
| **Backlog** | запланировано, не в текущем спринте | — |
| **To Do** | взята в спринт на планировании | — |
| **In Progress** | идёт работа | есть ветка `task/LCT-XX` |
| **Review** | код готов, ждём ревью | открыт PR |
| **Done** | PR смержен, критерии задачи выполнены | коммиты в `main` |

## 3. Как создать задачу (пошагово)

1. **Найти свободный ID** (запрещено переиспользовать):
   ```bash
   ls tracker/tasks/ | grep -oE 'LCT-[0-9]+' | sort -V | tail -1
   # → LCT-12, значит следующая LCT-13
   ```
2. **Создать файл** `tracker/tasks/LCT-13.md` (имя файла = ID задачи):
   ```markdown
   ---
   id: LCT-13; title: Короткий заголовок; column: Backlog; points: 2; assignee: sa100h; due: 2026-09-13; tags: backend;data
   ---
   # LCT-13 — Короткий заголовок

   Что нужно сделать и почему. Приёмка: как проверить, что задача сделана.

   ## Чек-лист
   - [ ] шаг 1
   - [ ] шаг 2
   - [ ] шаг 3
   ```
3. **Поля frontmatter** (строка после `---`, `;`-разделённая, одна строка):

   | Поле | Значение | Пример |
   |---|---|---|
   | `id` | `LCT-<номер>`, совпадает с именем файла | `LCT-13` |
   | `title` | заголовок, ≤ 10 слов | `Метрики предиктов в Grafana` |
   | `column` | ровно одно: `Backlog` / `To Do` / `In Progress` / `Review` / `Done` | `Backlog` |
   | `points` | story points: 1, 2, 3, 5, 8 | `3` |
   | `assignee` | git-username исполнителя | `sa100h` |
   | `due` | срок, `ГГГГ-ММ-ДД` | `2026-09-13` |
   | `tags` | теги через `;` | `ml;backend` |

4. **Сгенерировать дашборд**: `python3 tracker/gen_dashboard.py`
   (нужен Python 3.11+; на машине: `~/.hermes/hermes-agent/venv/bin/python`
   или любой другой с 3.11+).
5. **Коммит и пуш**:
   ```bash
   git add tracker/tasks/LCT-13.md README.md
   git commit -m "task/LCT-13: новая задача — метрики предиктов"
   git push
   ```

> Правило: **новая задача всегда стартует в `Backlog`**, даже если
> «сделаем сегодня» — в спринт её берут на планировании.

## 4. Как двигать задачу

Отредактировать одно поле `column:` в файле задачи, пройтись шаги 4–5 из
раздела 3. Всё. Чек-лист в задаче отмечает по ходу выполнения.

Пример: задача готова, PR открыт →

```diff
- id: LCT-07; title: Фронтенд: дашборд + заявки; column: In Progress; ...
+ id: LCT-07; title: Фронтенд: дашборд + заявки; column: Review; ...
```

## 5. Рабочий процесс команды

**Каждый день:**
- открыть README → увидеть доску, burndown и дни до дедлайна;
- после изменений в задачах: `gen_dashboard.py` → коммит (на `main`
  workflow `dashboard.yml` делает это сам, см. раздел 7).

**Спринт-планирование (1 раз в спринт):**
1. Пройтись по `Backlog` в README.
2. В `tracker/config.toml` указать спринт: `name`, `start`,
   `duration_days`, `capacity_points` (сумма points, которые команда
   реально закроет), `state = active`.
3. Перенести задачи из `Backlog` в `To Do` — ровно на сумму ёмкости
   (не больше!). Сумму проставленных points видно в chip-строке README.
4. Генерация дашборда → коммит → пуш.

**В течение спринта:**
- взял задачу: `To Do → In Progress`, создаёшь ветку `task/LCT-XX`;
- код готов: `In Progress → Review`, открываешь PR;
- ревью пройдено: PR merge → `Review → Done`, чек-лист все `[x]`.

**Definition of Done** (задача считается Done, когда):
- [ ] PR смержен в `main`, CI зелёный;
- [ ] все пункты чек-листа отмечены;
- [ ] результат воспроизводим (`docker compose up` → работает).

**Закрытие спринта:**
1. `config.toml`: `state = finished`, новые `name`/`start` для следующего.
2. Невыполненные `To Do`/`In Progress` возвращаются в `Backlog`
   (или остаются в колонке, но точним ёмкость — на выбор команды).
3. Короткий ретроспектива-заметок в `tracker/retro/sprint-1.md` (что
   пошло хорошо / плохо / улучшить).
4. Генерация → коммит.

## 6. Burndown — как читать

В README: `Осталось (факт)` — оставшиеся points задач спринта сегодня;
`Идеальный курс` — сколько должно было остаться по ровному темпу от
`capacity_points` к концу спринта. Факт выше идеала → сползание, на
планировании брать поменьше.

## 7. Автогенерация (GitHub Actions)

`.github/workflows/dashboard.yml`: любой push в `main`, затронувший
`tracker/**` или `README.md` → бот `niceplan-bot` сам запускает
`gen_dashboard.py` и коммитит `chore(tracker): regenerate dashboard`.

Менять **вручную** раздел README между `<!-- NICEPLAN:BOARD -->` и
`<!-- NICEPLAN:/BOARD -->` **нельзя** — при следующей генерации его
перепишут. Всё редактируете в `tracker/tasks/*.md` и `config.toml`.

Когда генерация НЕ сработает (ветка не main, workflow выключен):
запустите `python3 tracker/gen_dashboard.py` вручную и включите
`README.md` в коммит.

## 8. Правила и соглашения

- **1 задача ≈ 1 PR.** Небольшие правки можно группировать под одной
  задачей, большие (5–8 pts) лучше разбить на 2–3 задачи.
- **Не удалять задачи.** Брошенную — оставить в `Backlog`, в title
  пометить `[dropped]`; сделанную — в `Done`.
- **`assignee` = git-username**, под которым коммитите.
- **Comмиты** по задаче: `task/LCT-07: <что сделано>` — история
  автоматически становится журналом работ.
- Формат frontmatter: **одна строка**, разделитель `;`, без перевода
  строки внутри. Громоздкие описания — в тело markdown, не в frontmatter.
- ID задач — только увеличение; кэп на длину нет, но держитесь `LCT-XX`.
- Если задача не парсится — генератор напишет `! без frontmatter`
  и пропустит её: проверьте синтаксис строки frontmatter.

## 9. Шпаргалка

```bash
# доска
sed -n '/NICEPLAN:BOARD/,/NICEPLAN:\/BOARD/p' README.md

# следующая свободная ID
ls tracker/tasks/ | grep -oE 'LCT-[0-9]+' | sort -V | tail -1

# создать задачу
$EDITOR tracker/tasks/LCT-13.md        # шаблон — раздел 3

# пересобрать дашборд
python3 tracker/gen_dashboard.py

# коммит задачи
git add tracker/ README.md && git commit -m "task/LCT-13: <что>" && git push

# кто и что в колонке
grep -h 'column: Review' tracker/tasks/*.md
```

**Минимальный цикл за 2 минуты:** новый `LCT-XX.md` (шаблон выше) →
`gen_dashboard.py` → `git commit -am "task/LCT-XX: ..." && git push` →
README обновлён (вручную или ботом).
